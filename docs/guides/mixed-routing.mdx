This guide shows how to add both file-based and config-based routing to a Waku app. Use the experimental `unstable_createFileRoutes` inside `createPages` to register file routes, then add explicit routes with `createPage`.

The following example illustrates how`unstable_createFileRoutes(modules, options?)` registers file-based routes inside the `createPages` callback.

```tsx
// ./src/waku.server.tsx
import { createPages } from 'waku';
import adapter from 'waku/adapters/default';
import type { PathsForPages } from 'waku/router';
import { unstable_createFileRoutes } from 'waku/router/server';
import { AboutPage } from './templates/about-page';
import type { FilePages } from './pages.gen';

const pages = createPages(async (fns) => {
  await unstable_createFileRoutes(
    fns,
    import.meta.glob('./pages/**/*.{tsx,ts}'),
    { pagesDir: 'pages', apiDir: 'api' },
  );
  const { createPage } = fns;

  return [
    createPage({
      path: '/company',
      render: 'static',
      component: AboutPage,
    }),
  ];
});

export default adapter(pages);
```

File routes and config routes share pages, layouts, roots, slices, APIs, and interceptors in one router. File conventions and module configuration match `fsRouter`'s behavior. Duplicate page paths will fail instead of overriding a registration. Equivalent dynamic page patterns, such as `/users/[id]` and `/users/[name]`, will also fail. Static paths can still overlap dynamic patterns and retain their normal routing priority.

Application middleware remains an adapter option through `middlewareModules`.

## Known Limitations

1. For mixed routing, there is no automatic type generation such as `pages.gen.ts` (just like with config routes). However, you can still use `unstable_createRouteHref`(See [Typed Routes](./typed-routes.mdx)) to achieve fully type-safe navigation.
2. `unstable_createFileRoutes` does not accept `unstable_skipBuild`. Set that option on `createPages` to control build output for both sources.
